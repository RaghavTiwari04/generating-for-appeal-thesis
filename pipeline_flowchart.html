1 Data Collection & Feature Extraction Build the training corpus from live marketplaces
Data Marketplace Scraping
Scrape greeting card listings from Etsy, Redbubble, Zazzle, and Greetings Island. Extract title, description, price, review/favourite counts, images, and structured metadata via JSON-LD + CSS selectors.
Justification: real marketplace cards represent what consumers actually buy. Multi-source sampling reduces platform bias. ~2,377 cards across 27 occasion types.
data/scrapers/ → data/pipeline_runner.py steps: scrape, download
↓
Data CLIP Embedding
Compute normalised CLIP ViT-L/14 image + text embeddings (768-d) for every listing. Cached in DB for reuse.
Justification: frozen backbone features feed the predictor (no end-to-end fine-tuning = reproducible + cheap). Also used for deduplication and market signal clustering.
data/features/clip_embed.py
Data OCR + Palette + Complexity
OCR: Tesseract extracts headline text from card images.
Palette: Dominant LAB colour palette.
Complexity: Edge density score.
Justification: OCR provides text features for the predictor's text embedding input. Palette and complexity are used by the brief generator's market signals.
data/features/ocr.py, palette.py, image_complexity.py
↓
Data Occasion Classification
Fine-tuned DistilBERT multi-label classifier (27 classes) trained on keyword-matched weak labels. Assigns occasion tags to all listings.
Justification: marketplace search terms are noisy. Classifier standardises occasion labels so LoRA training, market signals, and evaluation conditions sample correct occasion subsets.
data/features/occasion_classifier.py — steps: clf-train, clf-infer
Data Deduplication
Three-signal duplicate detection: pHash (perceptual hash), CLIP cosine similarity, TF-IDF title similarity. Union-find clustering marks duplicates.
Justification: marketplaces host re-listings and template variants. Duplicates inflate apparent variety and bias training. Aggressive dedup ensures each LoRA training image contributes unique style signal.
data/features/dedup.py
2 Saleability Labelling Two complementary label sources: VLM (all cards) + human BT (subsample)
All ~2,377 cards
Label VLM 4-Head Labels
Send each card image to Claude Sonnet / GPT-4o with a structured scoring prompt. VLM returns four perceptual-quality scores:
occasion_fit — does imagery match occasion?
aesthetic — visual quality, composition, typography
emotional_resonance — does it evoke warmth/joy?
distinctiveness — original vs generic template
Justification: VLMs can reliably assess perceptual quality at scale (all cards) but cannot predict what people would actually buy. Inter-model agreement (Claude vs GPT-4o) validates consistency. These four heads provide dense supervision for the predictor's perceptual pathway.
data/labels/vlm_labels.py → stored as vlm_4head_v1
~500-card subsample
Human Prolific 2AFC Survey
Recruit participants on Prolific for a pairwise two-alternative forced-choice (2AFC) study. Participants see two cards and choose which they'd buy. Active-learning pair sampler selects maximally informative pairs.
Justification: purchase intent is fundamentally a human judgement — no VLM can reliably predict it. 2AFC avoids Likert scale calibration issues across participants. ~500 cards is sufficient for Bradley-Terry convergence.
survey/instrument/app.py (pairwise mode) → survey_pairs table
↓
Model Bradley-Terry Scaling
Fit Bradley-Terry model via MM algorithm (Hunter 2004) on pairwise comparison data. Recovers per-card log-odds scores, normalised to [0,1] via logistic transform.
Justification: BT converts ordinal pair preferences to interval-scale scores suitable for regression. Prior-regularised to handle cards with few comparisons. This produces the purchase_intent ground truth for predictor head 5.
survey/analysis/bradley_terry.py
3 Saleability Predictor Multi-head MLP trained on cached CLIP features — predicts saleability from card embeddings
Model Multi-Head Predictor Architecture
Inputs: CLIP image emb (768-d) + CLIP text emb (768-d) + occasion embedding (32-d) + log-price (1-d)
Trunk: 2-layer MLP (1569 → 512 → 512) with GELU + dropout
Heads: 5 independent heads (512 → 128 → 1 → sigmoid), one per quality dimension
Justification: frozen backbone + MLP avoids GPU-heavy fine-tuning. Multi-head architecture shares a trunk for efficiency while allowing per-dimension specialisation. Backbone is not loaded at training time — embeddings are pre-cached for speed and reproducibility.
models/predictor/architecture.py
↓
Model Masked Multi-Task Training
Loss: weighted masked MSE. Heads 1–4 (VLM) train on all ~2,377 cards. Head 5 (purchase_intent) trains only on the ~500-card BT-labelled subsample.
Masking: each head only backpropagates on samples where its label exists (Ruder 2017).
Weighting: purchase_intent head weighted 2× to compensate for smaller label set.
Optimiser: AdamW (lr=1e-4, wd=1e-2), cosine schedule, early stopping (patience=5).
Split: by seller_id 70/15/15 to prevent data leakage from same-seller card families.
Justification: masked loss elegantly handles the two-tiered label regime. VLM heads provide rich gradients for the shared trunk even where human labels are absent, improving purchase_intent generalisation through multi-task transfer.
models/predictor/train.py
↓
Model Isotonic Calibration
Fit isotonic regression on validation-set purchase_intent predictions vs. BT ground truth. Maps raw sigmoid outputs to calibrated probabilities.
Justification: sigmoid outputs of neural nets are rarely calibrated. Isotonic regression is non-parametric and monotone — it corrects the mapping without changing rank order. Calibrated scores are directly interpretable as "probability of being preferred in a pairwise comparison."
models/predictor/calibrate.py → purchase_intent_calibrated
4 Per-Occasion LoRA Training Style specialisation on Flux.1-dev via DreamBooth
Gen Text Erasure Preprocessing
Before LoRA training, erase baked-in text from marketplace card images using Tesseract OCR (word-level bbox detection, conf ≥ 10) + OpenCV Telea inpainting (radius=7). Dilates bboxes by 15% to catch serifs and shadows.
Justification: marketplace cards have printed greetings. Without erasure, LoRA learns text-as-texture artifacts — the model would reproduce garbled letterforms in generated images, interfering with the clean typography overlay step.
generation/image/loras/train_lora.py → _erase_text_regions()
↓
Gen DreamBooth LoRA Fine-Tuning
For each active occasion (e.g. birthday/general), select top ~150 images by VLM saleability score. Train a LoRA (rank 8–16, ~1000 steps) on Flux.1-dev via diffusers DreamBooth.
Instance prompt: "a greeting card for {occasion}"
Config: bf16 mixed precision, gradient accumulation 4, lr=1e-4, constant schedule.
Justification: LoRA adapts Flux to the visual vocabulary of each occasion (birthday cakes, Christmas trees, sympathy florals) without full fine-tuning. Training on top-saleability images biases the generator toward commercially successful styles. Separate LoRA per occasion prevents cross-contamination.
generation/image/loras/train_lora.py → weights saved to generation/image/loras/{occasion}/
5 Card Generation Pipeline Request → brief → image → layout → message → rerank
LLM Brief Generation
Given a request (occasion, tone, relationship), query market signals (top tropes via CLIP KMeans clustering, coverage gaps, longevity caution) then prompt Claude / GPT-4 with a structured template. LLM returns a Brief:
concept, headline (≤90 chars), inside_message, visual_prompt, negative_prompt, style_tags (≤4), target_price_band
Justification: market signals inject data-driven trends into the creative brief, steering the LLM away from generic prompts. The structured schema ensures downstream steps have all required fields. Longevity caution prevents time-bound references that age poorly.
generation/brief/generate.py + market_signals.py
↓
Gen Headline Mask
Build a binary mask image reserving a rectangular region (default: top-left, 55% × 25% of canvas) for headline text. Feathered edge (24px Gaussian blur) for smooth transitions.
Justification: if the diffusion model fills the entire canvas with complex imagery, text becomes illegible. The mask ensures a low-detail region exists for typography overlay. This is purely geometric — no neural network needed.
generation/image/headline_mask.py
Gen Flux.1 Image Generation ×N
Generate N candidate images (default N=8) using Flux.1-dev with occasion-specific LoRA loaded. If mask provided, uses Flux Fill (native inpainting) to keep the masked region low-detail. 30 inference steps, guidance 7.0.
Justification: Flux.1 outperforms SDXL on text rendering, fine detail, and prompt adherence (Black Forest Labs, 2024). Flux Fill handles inpainting natively without a separate ControlNet. Generating N candidates enables best-of-N reranking.
generation/image/diffusion.py — base: FLUX.1-dev, inpaint: FLUX.1-Fill-dev
↓
Gen Typography Composition ×N
For each of the N generated images:
1. Font selection — rule-based mapping from (tone, style_tags) to curated Google Fonts
2. Binary-search sizing — find largest font size that fits bbox after natural-phrase line breaks
3. Contrast colour — pick black or white based on mean LAB luminance of the bbox patch
4. Render — Pillow text drawing with subpixel anti-aliasing
Justification: rule-based typography is deliberately boring — predictable, controllable layouts are better for thesis evaluation than a learned layout model with unpredictable failures. Binary search guarantees the text fits. Contrast check ensures readability on any background.
generation/layout/compose.py + generation/layout/font_palette.py
↓
LLM Inside Message Generation
Prompt LLM with occasion, tone, concept, and headline to generate the inside message (what you read when you open the card). Returns a primary message + up to 3 alternatives. Prompt includes a cliché blacklist to avoid generic phrases.
Justification: the inside message is a separate creative artefact from the cover. Generating it after the brief and cover ensures coherence with the chosen concept and headline. Cliché avoidance pushes toward distinctive messages (which the distinctiveness head rewards).
generation/message/generate.py
↓
Model Best-of-N Reranking
Score all N candidates with the 5-head predictor (via cached CLIP embeddings). Compute composite saleability:
saleability_calibrated = 0.7 × purchase_intent_calibrated + 0.3 × distinctiveness
Sort by composite. Return top-k (default k=1 for eval, k=3 for production).
Justification: best-of-N selection is the core thesis contribution — it uses the learned predictor to filter out low-quality candidates before they reach users. The 0.7/0.3 weighting ensures purchase intent dominates but distinctiveness breaks ties, promoting variety. The distinctiveness component is tested via ablation (removing it = the no_distinctiveness ablation).
pipeline/rerank.py + models/predictor/infer.py
↓
Data Persist to DB
Store the top-k cards in generated_cards table with: pipeline version, condition tag, full brief JSON, cover image path (MinIO), inside message, headline text, all predicted scores, seed.
Justification: full provenance enables reproducibility. Condition tags partition cards for evaluation. Seeds allow exact regeneration of any card.
pipeline/orchestrator.py → generated_cards table
6 Evaluation Four conditions, human 2AFC study, ablations, failure analysis
Eval Four Evaluation Conditions
Generate cards under controlled conditions to isolate each pipeline component's contribution:
A: Naive AI Flux + generic prompt + headline mask + typography.
No LoRA, no brief LLM.
B: Pipeline (N=1) Full pipeline (LoRA + mask + layout + LLM message), single candidate.
No reranking.
C: Pipeline + Rerank Full pipeline, N=8 candidates, predictor-based best-of-N selection.
Primary system.
D: Human Bestsellers Real cards from marketplace, sorted by review + favourite count.
No generation.
Justification: A→B isolates LoRA + LLM brief. B→C isolates the reranking contribution (core thesis claim). C↔D benchmarks against real products. Condition A uses the same mask + typography as B/C so the only ablated variable is prompt quality and LoRA.
pipeline/conditions.py
↓
Human Prolific Pairwise 2AFC Study (Main)
Participants on Prolific see two cards side-by-side (from any two conditions) and choose which they'd buy. Active-learning sampler selects maximally informative pairs.
Analysis: Fit Bradley-Terry model across all cards. Group BT sale_scores by condition. Test pre-registered hypotheses via Holm-corrected Mann-Whitney U pairwise tests:
H1: C > A    H2: C > B    H3: C ≈ D
Justification: 2AFC avoids Likert calibration issues. BT scaling recovers interval-scale scores from ordinal pairs. H1 tests whether the full pipeline beats naive generation. H2 tests whether reranking adds value. H3 tests whether AI cards approach human-designed quality.
eval/system_eval_bt.py + survey/analysis/bradley_terry.py
↓
Eval Predictor Evaluation
Per-head Spearman ρ vs. held-out human labels. Calibration reliability diagram + ECE. Ridge regression baseline comparison.
Justification: validates that the predictor actually learned meaningful quality signals, not noise.

Justification: quantitative metrics show the system works on average but miss individual failure modes. Manual coding identifies systematic weaknesses and future work.

7 Study Design & Power Analysis Pre-registration support
Eval Monte Carlo Power Simulation
Simulate BT studies with varying N (participants, pairs per participant, cards) and effect sizes. For each configuration, generate synthetic pair outcomes, fit BT, and compute power = P(reject H0 | H1 true). Outputs the minimum sample size to detect a given effect at α=0.05, power=0.80.
Justification: required for Prolific ethics approval and pre-registration. Ensures the study is powered to detect the expected effect size from pilot data. Prevents underpowered studies that waste participant time and funding.

Pipeline Summary
Core thesis claim: a learned saleability predictor, used as a best-of-N reranker, measurably improves AI-generated greeting card quality as judged by human purchase intent.

Data flow: Scrape marketplace → extract features → VLM + human labels → train multi-head predictor → generate N cards with LoRA-adapted Flux → rerank by composite saleability → validate via human 2AFC study.

Key design choices:
• Flux.1 over SDXL — better prompt adherence and fine detail
• LoRA per occasion — style specialisation without full fine-tuning
• Text erasure before LoRA — prevents text-as-texture artifacts
• Masked multi-task loss — leverages dense VLM labels + sparse human labels
• Composite reranking (0.7 PI + 0.3 dist) — balances quality and variety
• 2AFC over Likert — avoids cross-participant calibration issues
• Bradley-Terry scaling — converts ordinal pairs to interval scores
• Condition A with headline mask — fair ablation (only prompt/LoRA differ)
